# Заметки и поручения на доске

Доска содержит общий с агентом слой и личный слой человека. Это отдельные
данные поверх снимка процесса. Читай только результат `readProcessBoardForAgent`:
он скрывает личный слой на сервере. Не ищи скрытые заметки через другие API.

Чтение всей доски, изображений и связей — по [board.md](board.md).
Отметка «Поручение агенту» служит для учёта состояния и ответа на стикере.
Она не обязательна для выполнения просьбы из диалога. Без отметки ответь
в диалоге; не требуй от человека создавать заметку ради работы с материалами.

`targets` и `attachments` — прямые общие связи заметки, не полный набор
материалов задачи. Учитывай остальной граф доски. `task: null` означает
отсутствие учёта поручения, а не запрет использовать заметку как контекст.

## Обработка поручения

1. Прочитай свежую доску. `open` — ожидает разбора, `needs-info` — требует
   решения человека, `done` — уже выполнено. Не выполняй повторно неизменённое
   `done` и не задавай снова уже записанный вопрос без новых данных.
2. Пойми требуемый результат и область изменения. Существенное изменение
   бизнес-правил согласуй и отрази в знаниях/плане по обычной процедуре.
   При неясности сохрани `needs-info` с конкретным вопросом и передай его
   в диалоге понятным владельцу языком. Независимую работу продолжай.
3. Выполни разрешённую часть, проверь результат и обнови карту по
   [процедуре](procedure.md). Не отмечай поручение выполненным лишь потому,
   что прочитал его или внёс правку в файл. Ответ «выполнено» касается
   именно поручения, а не готовности всего процесса к запуску.
4. Перечитай заметки после обновления карты. Сравни текст, цели и ревизию
   поручения с теми, по которым работал. Если поручение изменилось, оцени его
   заново; не закрывай новую просьбу результатом старой.
5. Подготовь короткий ответ обычным языком: что изменилось и где посмотреть
   либо какое решение требуется. Запиши его отдельным текстовым файлом вне
   аккаунта. Сохрани ответ через команду ниже и проверь чтением доски.

```sh
node .agents/skills/processes/scripts/board.mjs respond-note <process> \
  --from <сохранённый-json-чтения> --note <id-заметки> \
  --status done --message-file <файл-ответа>
```

Для вопроса используй `--status needs-info`. Ответ ограничен 2000 символами.
Перед `done` скрипт проверяет актуальность сохранённой карты, коммит и ревизии.
Сервер сверяет ревизии доски, снимка и самого поручения; запись ответа не
меняет заметку, стрелки, личный слой, план или состояние процесса.
При конфликте перечитай доску и повторно оцени поручение. При сетевой ошибке
сначала прочитай доску: ответ мог сохраниться. Не повторяй запись вслепую.

Человек видит состояние на стикере, ответ — в его свойствах. Правка текста,
общих связей или связанного изображения открывает поручение заново;
перемещение и оформление этого не делают. «Вернуть агенту на рассмотрение»
открывает прежний текст повторно после сохранения доски. Снятие отметки прекращает учёт на стикере, но не отменяет отдельную просьбу
из диалога. Удаление или скрытие материала требует заново оценить контекст
поручения; не продолжай использовать скрытый материал по старому снимку.

## Границы

Сохранение доски не запускает агента и не подставляет заметки в каждый
запрос автоматически. Нужен следующий вызов `context` или `board read`.
Для записи ответов нужен Start с публичным `respondToProcessBoardNote`.
Старый SDK остаётся пригоден для чтения общих заметок, но не подтверждает
ни поручения, ни сохранение ответа. Не подменяй SDK внутренними маршрутами.
При переносе процесса в другую ветку заметки автоматически не переносятся:
доска хранится для пары процесс + ветка.
