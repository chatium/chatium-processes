# Окружение и установка

Скилл работает в Git-аккаунте Chatium. Факты о бизнесе, домен, ID аккаунта,
ветки, контакты и настройки интеграций берутся из текущего аккаунта и
согласованных материалов пользователя. Значения из примеров не являются
настройками установленного скилла.

## Файлы и зависимости

Установи каталоги целиком, сохраняя структуру:

```text
<корень аккаунта>/.agents/skills/chatium-processes/SKILL.md
<корень аккаунта>/.agents/skills/chatium-development/SKILL.md
```

`chatium-development` — обязательная зависимость: он содержит справки
платформы и включается в библиотеку независимых ревьюеров. Оба скилла
должны быть доступны основному агенту и его субагентам. Команды в инструкции
рассчитаны на эту установку и запуск из корня аккаунта. При другом размещении
используй фактический путь к скриптам и `--root <корень-аккаунта>`; сохраняй
соседство двух каталогов скиллов.

Оба скилла устанавливаются штатным CLI в `.agents/skills/` и `.claude/skills/`
и не отслеживаются Git аккаунта. После свежего клонирования или смены среды
проверь наличие обоих входных файлов. Для установки или обновления выполни
из корня аккаунта:

```sh
chatium get-skills
```

Команда загружает актуальную опубликованную версию обоих скиллов и заменяет
их локальные копии. Не исправляй установленный скилл и не коммить его в
аккаунт: обновление перезапишет такие изменения. После команды проверь оба
входных файла; если загрузка не удалась, нельзя считать зависимые ревью
доступными.

Нужны Node.js 22 или новее, Git и Chatium CLI (`chatium` в `PATH`).
Npm-зависимости скриптов — `yaml` для файлов процесса и `js-yaml` 4.3.2
для плана тестирования с теми же правилами разбора, что в Start.
Для воспроизводимой установки зависимостей самого скилла:

```sh
(cd .agents/skills/chatium-processes && npm ci --ignore-scripts)
```

Команда использует включённый `package-lock.json` и не меняет зависимости
приложения. Не добавляй `node_modules` в Git. Загрузчик проверяет оба пакета
рядом со скиллом, затем в аккаунте и окружении. Явный `PROCESSES_YAML_PATH`
имеет приоритет: это каталог, от которого разрешаются `node_modules/yaml`
и `node_modules/js-yaml`. Если пакеты уже доступны из окружения агента,
дополнительная установка не нужна; наличие только `yaml` недостаточно
для команд тестирования. При отсутствии `js-yaml` выполни указанную установку.

## Доступ к платформе

- `origin` должен указывать на Git-репозиторий текущего аккаунта.
- CLI должен быть авторизован для этого аккаунта. Используй штатный `chatium`
  из `PATH`, сохраняя предусмотренную окружением обёртку.
- Для карты нужен установленный Start с `writeProcessSnapshot` и
  `readProcessBoardForAgent` в `@start/sdk`; для ответов на поручения —
  `respondToProcessBoardNote`. Перед сетевой проверкой версия
  ветки должна быть опубликована; правила — [map-freshness.md](map-freshness.md).
- Для страниц, писем, оплат и других интеграций нужны соответствующие
  модули аккаунта и их актуальные typings. Подключённые каналы, провайдеры
  и права проверяй в текущем аккаунте по `chatium-development`.

Локальные режимы `--no-snapshot` и `context --offline` позволяют работать
до публикации, но не подтверждают актуальность карты или доступность SDK.

## Плагины аккаунта

Перед сборкой проверь, какие возможности нужны согласованному пути клиента:
Mailings для шаблонов сообщений, Automations для реакций на события, Sender
для доставки и нужные транспорты, включая SMS; другие плагины — по задаче.
Не предполагай, что они уже установлены, и не устанавливай весь список
«на всякий случай». Уточни фактические Store slug, доступность, стоимость и
права каждого нужного плагина через `getPluginInstallInfo` из `@store/sdk`.

Для Source Git-аккаунта агент с Admin-доступом может установить опубликованный
доступный плагин через `installPlugin` из `@store/sdk`, вызвав его посредством
`chatium exec`. Поручение собрать согласованный процесс включает установку
необходимых **бесплатных** плагинов, если владелец не ограничил изменения
аккаунта; после проверки прав установи их и сообщи владельцу о результате и
правах. Платную покупку или плагин вне согласованного объёма не выполняй
молча. Если SDK вернул `checkout_required`, установка не состоялась.

Точный контракт, проверки разрешений, обработка ошибок и правило повторного
вызова бери из `chatium-development/store-plugin-install.md` и
`chatium-development/exec.md`. После установки проверь наличие требуемого SDK
и его typings в аккаунте. Подключение канала, настройка отправителя и оплата
провайдера — отдельные действия; установка плагина не означает их готовность.

Для изолированных тестов входящих/исходящих сообщений внешний канал не нужен:
используй внутренний транспорт Sender с TestContext по
`chatium-development/sender-test-transport.md` и [правилам сценариев](../formats/test-records.md#внутренний-транспорт-сообщений).
Он не заменяет подключение канала для реальных клиентских отправок.

Для проектирования и сборки достаточно определить бизнес-канал (email,
мессенджер и т. п.); отсутствие его подключения и реального тестового контакта
не блокирует этап. Не добавляй внутренний тестовый channelId в `senderChannels`.
Сохрани подключение реального транспорта в «Нужно от вас» с `blocks: [launch]`.

Перед приёмкой внешней доставки и боевым запуском получи активные каналы через `getChannels(ctx)` из
`@sender/sdk`. Если подходящего канала нет, открой в Sender
`/app/sender#/transports/add` для владельца и укажи необходимость подключения;
продолжай сборку и внутренние тесты. Для внешней почты
может потребоваться сначала установить её официальное приложение из этого
раздела. Затем повтори `getChannels(ctx)`, проверь `type` и `active` и запиши
фактический ID в `config.senderChannels` и задание серии. Порядок выбора
канала и его типы описаны в `chatium-development/sender-entities.md`.

## Возможности агента

Нужны чтение и изменение файлов аккаунта, запуск команд и инструмент
независимого субагента с доступом к пакету и библиотеке справок. Конкретный
вызов выбирается по доступной схеме: [ревью знаний](../method/review.md).
Если делегирование недоступно, проектирование и разрешённые правки можно
продолжать, но независимое ревью и готовность не считаются подтверждёнными.

Пакет ревью храни вне репозитория в папке, доступной обоим агентам и
сохраняющейся между вызовами инструментов. `prepare --out <папка>` задаёт её
явно. По умолчанию используется `/data/external`, если такой каталог есть
в среде Chatium, иначе системная временная папка.

При наличии инструмента превью открывай результаты по [preview.md](preview.md).
Если инструмент недоступен, передай рабочую ссылку и сообщи, что панель
не открыта. Отсутствующие права и инструменты не заменяй заявлениями об успехе.

Для работы со скриншотами нужен инструмент, который передаёт изображение
модели (просмотр изображения или браузер). `board material` получает URL
через `@app/storage`, но не анализирует картинку сам. Выбирай доступный
инструмент по его схеме; без визуального доступа содержимое не считается
изученным. Подробнее — [board.md](board.md).
