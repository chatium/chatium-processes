# Превью процесса и его частей

Показывай карту в панели превью, когда пользователь просит открыть процесс,
и на контрольных точках работы ниже. Способ открыть панель и маршруты
страниц, писем, знаний и автоматизаций — в `chatium-development`,
[preview.md](../../chatium-development/preview.md).

## Адрес карты

```text
/app/start/process-map?process=<папка-процесса>&branch=<ветка>
```

Оба параметра обязательны в ссылке агента. `process` — путь папки процесса
от корня аккаунта (слаг процесса), `branch` — ветка **этого процесса**. Береги
`/` внутри имени ветки: используй `URLSearchParams`, не ручную склейку.

```javascript
const url = new URL('/app/start/process-map', accountUrl)
url.searchParams.set('process', processSlug)
url.searchParams.set('branch', branch)
```

Например:
`/app/start/process-map?process=trial-class&branch=process%2Ftrial-class`.
Это пример формата, не указание использовать такую ветку. Без названной
пользователем ветки возьми текущую через `git branch --show-current`;
после merge/push в `main` показывай `branch=main`. В detached HEAD выясни целевую
ветку из задачи/артефактов, не называй `HEAD` веткой и не угадывай её.

Карту открывай в опубликованном Start. Параметр `branch` выбирает снимок
процесса; отдельный preview-scope для Start не добавляй.

## Откуда берётся схема

`process.yaml` — редактируемое описание, снимок карты хранится в Heap
Start для пары процесс + ветка. Само появление YAML не создаёт снимок.
Перед показом нового результата: заверши файловые правки → commit → push
разрешённой ветки → `check --publish-snapshot` → читающий `check`.
При показе проекта до сборки добавь к обеим командам
`--task-stage design --knowledge-stage design`. Нужны успешная запись и контрольное чтение
(`snapshot.verified: true`). Детали — [map-freshness.md](map-freshness.md).

При показе проекта до сборки красные технические проверки допустимы:
покажи актуальную схему и объясни, что ещё не построено. Не жди полной
зелёной готовности, чтобы обсудить идею. Для заявления «готово» нужны обе
вещи: актуальный снимок и зелёные проверки, включая независимое ревью знаний.
`--no-snapshot` ничего на доске не обновляет.

По просьбе «покажи процесс» сначала открой выбранный сохранённый снимок:
для просмотра не требуются новый commit, merge или публикация. Если снимок
устарел/отсутствует, сообщи это; обновляй только в рамках разрешённой работы.
Не показывай старую карту как результат ещё не опубликованных правок.

## Когда открывать автоматически

1. **Идея спроектирована:** есть осмысленный `PLAN.md` и `process.yaml`;
   сохрани снимок и открой карту перед обсуждением «строим так?».
2. **Завершена часть процесса:** после доступности её новой версии открой
   страницу по прямому маршруту, письмо в Mailings, статью в reader знаний,
   автоматизацию через `/app/automations/~view?path=<путь-к-файлу.automationConfig.json>`.
   Для `path` используй полный путь от корня аккаунта и `URLSearchParams`;
   просмотр не включает автоматизацию.
   После работы над серией открой её папку через UI Mailings. Для показа
   нескольких статей достаточно основного обзора со ссылками на остальные.
3. **Согласование запуска:** после проверок открой карту текущей ветки;
   из неё и ссылок пользователь должен понимать, что станет боевым.
4. **Финал работы над процессом:** после последнего `check` открой карту
   последней, чтобы пользователь остался на общем результате. После
   разрешённого запуска — карту `main`, а не слитой рабочей ветки.

Не переключай панель на каждую техническую правку и не обходи предупреждение
об открытых несохранённых правках пользователя. Если открытие/авторизация
не удалось, дай полную ссылку, процесс и ветку; не утверждай, что показал
карту. Для агента используй маршрут из доступной справки платформы; не придумывай URL.
