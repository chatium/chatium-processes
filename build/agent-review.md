# Ревью самостоятельных помощников

После сборки принятой ИИ-роли и до живого теста проведи отдельное смысловое ревью. Общий code-review проверяет безопасность и соответствие плана коду; здесь независимый reviewer проверяет качество инструкций, фактические знания, действия, маршрут, передачу и сценарии. Этот шаг не запускается автоматически от изменения файла.

Перед передачей пакета проследи каждый составной путь инструментов на одной версии исходников: выход предыдущего шага → модельный параметр следующего → серверный выбор записи → побочный эффект. Сверь смысл похожих полей, например ID занятия и ID заявки. Включи в `agents/cases.yaml` отказ на чужую, отсутствующую и неоднозначную запись и продолжение старого разговора после изменения контракта. Несоответствие, оставленное одной лишь инструкцией модели, считается пробелом ревью.

Для каждой записи `handoffs[]` проверь связанный `case` и фактический способ передачи: опубликованную цель `redirect2` с нужным целевым ID либо серверный обработчик с вызовом SDK. Наличие файла обработчика и зелёный структурный `check` не доказывают перенос CRM-клиента, разрешённого контекста и остановку старых касаний; это входит в общий тест перехода.

При передаче человеку через сохранённое обращение проверь доступ к его карточке и состояние клиента **на момент чтения**, а не только при постановке. Сотрудник должен увидеть остановку контактов, наступившую позже. Отсутствие такого сигнала — замечание перед реальным запуском; показ уведомления в другом плагине проверяй отдельно.

```sh
node .agents/skills/processes/scripts/agent-review.mjs prepare <process>
```

Команда создаёт `packet.json`, `prompt.md` и неизменяемый снимок справок вне аккаунта. Передай содержимое `prompt.md` отдельному субагенту с чистым контекстом через инструмент своего окружения. Он читает два входных `SKILL.md`, обязательные разделы из `referenceLibrary.required`, затем нужные справки и typings выборочно. Пакет включает фактические инструкции, локальный код, знания, план и сценарии; не редактируй исходники до ответа.

Сохрани полный JSON-ответ ревьюера в файл вне аккаунта и запиши результат:

```sh
node .agents/skills/processes/scripts/agent-review.mjs record <process> \
  --packet <путь-к-пакету>/packet.json --report <путь-к-ответу>.json --agent <ID-вызова>
node .agents/skills/processes/scripts/agent-review.mjs status <process>
```

Скрипт проверяет полный ответ и цитаты, хеш входных материалов и справок, принадлежность отчёта независимому вызову. Устаревший отчёт, отсутствующий ответ или блокер не дают считать роль готовой к тесту. Блокер означает дефект или риск **самого контролируемого теста**; отсутствие результата ещё не проведённого испытания записывается как условие теста, а не тупик предварительного ревью. После исправления исходников собери один новый пакет и повтори ревью. Общий `check --task-stage test|launch` отдельно требует записанную проверку опубликованных конфигов и маршрутов через `agents-runtime.mjs --route-tests FILE --record`. Она читает актуальный канал и использует локальные тестовые контакты вне Git-аккаунта с методом SDK `dryRunProcessChannelRouting`; для полной проверки нужны новый и существующий CRM-клиенты. Живой прогон эффектов, вход без CRM-ключа и перенос контекста проверяй отдельно по [карточке помощника](../blocks/ai-agent.md). Для `test` результат действует сутки, для `launch` — 15 минут: маршрут общий и может измениться без Git-коммита. Сохрани наблюдения общего прогона в `<process>/tests/ai-*.json` или `agent-*.json`: пакет ревью включает эти файлы и при итоговой сдаче потребует одно повторное заключение по результатам, без раунда на каждую микроправку. Зависимость от интерфейса уведомлений другого плагина отмечай отдельно, если её проверка отложена владельцем.
