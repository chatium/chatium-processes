# Решение владельца вопреки существенной рекомендации

Если владелец выбирает вариант с существенным названным риском вопреки
рекомендации агента, сохрани отдельную запись
`<process>/decisions/risk/RD1.json` (затем `RD2.json` и т. д.). Для обычных
решений такой файл не нужен. Не объединяй несколько разных решений в один:
ревьюер должен ответить по каждому ID отдельно.

```json
{
  "version": 1,
  "id": "RD1",
  "recommendation": "Предложенный более безопасный вариант",
  "choice": "Что именно выбрал владелец",
  "consequence": "Названное владельцу существенное последствие",
  "scope": "Где решение действует и где не действует",
  "control": "Как заметить проблему и что сделать",
  "owner": {
    "message": "Дословный ответ владельца",
    "messageReference": "Ссылка или идентификатор сообщения, если доступен",
    "answeredAt": "2026-10-07T10:00:00.000Z"
  }
}
```

`owner.messageReference` можно опустить, если среда не даёт устойчивой
ссылки; дословный `owner.message` и время ответа обязательны.

Суть выбора и его последствия также остаются в подходящей статье знаний и
плане; запись не заменяет эту документацию. `kb-review` добавляет вопрос
`risk.RD1` для каждого файла и не принимает общее положительное заключение
вместо ответа по каждому решению. Если один из ответов отсутствует или
блокирует этап, заключение не готово. Файлы с ID не доказывают авторство
сообщения: без защищённого подтверждения платформы это запись на доверии.
