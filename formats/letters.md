# Письма: `.mailings/storage/processes/<process>/<series>/*.message.yaml`

Все письма аккаунта лежат в центральном хранилище `.mailings/storage/`.
Письма процесса — в `processes/<process>/`, по подпапке на серию. Редактор
писем Chatium Code открывает эту папку, и владелец может сам поправить
тексты. Если в хранилище есть `EMAIL_STYLE.md` — прочитай его и следуй ему.

`.mailings/storage/` — отдельный воркспейс. Если сессия запущена в
воркспейсе процесса, запись писем попросит подтверждения — это нормально.

Рантайм берёт письма не из этих файлов, а из собранного
`<process>/actions/letters.generated.json`. После любой правки писем —
`node .agents/skills/processes/scripts/letters.mjs <process>`.

## Имя файла

`<NN>-<key>.message.yaml`: номер в серии и ключ латиницей, например
`01-welcome.message.yaml`. Путь от корня аккаунта — это адрес письма для
шага отправки.

## Поля

```yaml
title: Вы зарегистрированы
description: Подтверждает регистрацию и даёт ссылку на эфир
order: 1
subject: "{{name}}, вы зарегистрированы на вебинар"
preheader: Ссылка на эфир внутри
plain: |+
  <b>{{name}}</b>, вы зарегистрированы!

  Эфир пройдёт {{webinar_date}}. Ссылка: {{webinar_url}}
html: |
  <div style="max-width:600px;margin:0 auto;font-family:Arial,sans-serif">
    <p><b>{{name}}</b>, вы зарегистрированы!</p>
    <p>Эфир пройдёт {{webinar_date}}.</p>
    <p><a href="{{webinar_url}}">Перейти к эфиру</a></p>
  </div>
variables:
  - name: name
    description: Имя получателя из заявки
    required: true
    example: Анна
  - name: webinar_date
    description: Дата и время эфира
    required: true
  - name: webinar_url
    description: Ссылка на комнату эфира
    required: true
```

| Поле | Правило |
| --- | --- |
| `title`, `description` | Всегда. Название для редактора и зачем письмо |
| `subject` | Всегда. Тема, одна строка без HTML |
| `plain` | Всегда. Текст для мессенджеров; допустимы `<b>`, `<i>`, `<u>`, `<s>`, `<a>`, `<code>`, `<pre>`, `<blockquote>`, без Markdown |
| `html` | Всегда. Email-вёрстка: inline-стили, контейнер до 600 px, без JS, форм, iframe, flex/grid |
| `preheader` | Для email, одна строка |
| `short` | Только если нужен SMS |
| `order` | Номер в серии, целое больше нуля |
| `variables` | Все и только используемые переменные |
| `buttons`, `media`, `attachments` | По необходимости |

Не создавай поля `id`, `key`, `path`, `email`, `telegram`, `delay`,
`trigger`, `schedule`, `status`, `metadata`, `agentPrompt`: их нет в схеме
письма. Задержки и условия живут в автоматизации, не в письме.

## Переменные

- Синтаксис только `{{name}}`: латиница в нижнем регистре и `_`, начинается
  с буквы. Без фильтров и значений по умолчанию (`{{name|друг}}` нельзя).
- Каждую переменную из `subject`, `preheader`, `plain`, `html`, `short`,
  кнопок объяви ровно один раз в `variables`. Неиспользуемые — убери.
- Значения подставляет Sender при отправке; не переданная переменная молча
  станет пустой строкой. Значения передаёт шаг автоматизации
  параметрами `var_<name>` (см. карточку
  [серии сообщений](../blocks/message-series.md)). `check` сверяет, что
  каждая объявленная переменная приходит в шаг.
- Известную постоянную ссылку можно написать прямо в тексте.

## Содержание

- Во всех представлениях совпадают факты, даты, цены и главное действие.
- Не выдумывай адрес отписки, реквизиты, подпись, логотип — бери из базы
