# Агенты процесса

Создавай эти файлы только для **принятого** применения ИИ в новом процессе. `agents/spec.yaml` описывает связи и проверяемые требования, а не дублирует бизнес-факты, длинные инструкции или платформенный конфиг. Общие факты — в базе знаний, исполняемые инструкции — в `.agent.json`. Старые процессы автоматически не переводятся на этот формат.

```yaml
# <process>/agents/spec.yaml
version: 1
opportunities:
  - id: lead-help
    need: Помочь человеку выбрать подходящую услугу после заявки
    decision: accepted # accepted | declined | deferred
    reason: Владелец согласовал помощь до разговора с менеджером
agents:
  - key: lead-helper
    config: <process>/agents/lead-helper.agent.json
    node: lead-helper
    opportunity: lead-help
    role: Консультант по заявкам
    outcome: Уточнить потребность и подготовить запись для менеджера
    boundary: Не обещать цену и время без проверки; сложный случай — человеку
    inputs:
      - kind: sender
        source: Канал заявок
    knowledge:
      - .knowledge-base/processes/<process>/offer.md
    tools:
      - name: Проверить доступное время
        source: <process>/agents/tools/availability.ts
    cases: [first-contact, no-slots]
routes:
  - channel: Канал заявок
    firstAgent: lead-helper
    existingConversation: Продолжать цепочку её текущего агента
    fallback: lead-helper
    # После отдельного тестового разговора:
    # testExistingChainKey: test-customer-001
    # expectedExistingAgent: lead-helper
handoffs: []
```

`config` и `node` должны совпадать с `source` и `id` узла `kind: agent` в `process.yaml`. `key` — устойчивое имя внутри процесса. После первой публикации получи настоящий `agentId`, запиши его в узел карты, опубликуй это изменение и обнови снимок; иначе на карте не будет перехода к агенту. `knowledge` перечисляет существующие локальные источники, **доступность в рантайме проверяется отдельно**. `tools` описывает требуемые действия и источники, но регистрация и разрешения тоже проверяются отдельно. `routes` описывает требуемый маршрут, не изменяет настройку канала само по себе. После подключения канала в `channel` запиши его точный Sender ID. Простой публичный SDK задаёт только одного адресата по умолчанию; отдельный запасной агент требует явных правил маршрутизации.

При передаче добавь в `handoffs[]` поля `from`, `to`, `when`, `summary`, `context`, `onFailure`: кому и когда передавать, что сообщить следующему помощнику, какой серверный контекст сохранить и что делать при сбое. Если `when` — достижение проверяемого результата, настрой в исходном `.agent.json` цель `redirect2` по [карточке агента](../blocks/ai-agent.md); в `redirectToAgentIds` нужны опубликованные платформенные ID, а не ключи из этой спецификации. `summary` в `spec.yaml` — требование к передаче, не автоматически сформированное сообщение: фиксированный `goal.messageText` не подставит факты конкретного клиента. Избегай циклов без бизнес-условия выхода. Для работы без общего канала `routes` может быть пустым; предупреждение `check` тогда нужно разобрать и записать источник входа в `inputs`. `testExistingChainKey` — ключ только тестового существующего разговора, `expectedExistingAgent` — его ожидаемый текущий помощник; без них автоматическая проверка продолжения вернёт частичный результат.

```yaml
# <process>/agents/cases.yaml
version: 1
cases:
  - id: first-contact
    agent: lead-helper
    situation: Клиент спрашивает о записи после заявки
    expected: Уточняет потребность, проверяет время, предлагает следующий шаг
    evidence: Тестовая запись создана или честно объяснено, почему это невозможно
  - id: no-slots
    agent: lead-helper
    situation: Свободного времени нет
    expected: Не выдумывает время, предлагает согласованный запасной путь
    evidence: Нет ложной записи; передача человеку видна в тестовом состоянии
```

Для реальных действий у каждого сценария заранее опиши тестовые контакты и данные, допустимый эффект, предел ходов/расходов и способ остановки. Реплика «готово» не подтверждает запись или передачу; сравни её с состоянием системы. Не запускай живой тест, пока получатели и инструменты не ограничены тестовым контуром. AI-генерацию рассылок пока не включай в процесс.
