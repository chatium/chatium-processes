# Карта процесса: `<process>/process.yaml`

Карта — смысл процесса на языке бизнеса плюс технические якоря. По якорям
`check` проверяет, что всё построено, а экран процесса и аналитика считают
людей. Пишет и поддерживает карту агент; статус узла в карту не пишется —
его даёт `check`.

## Пример

```yaml
title: Регистрация на вебинар
knowledge: .knowledge-base/processes/webinar-demo/
letters: .mailings/storage/processes/webinar-demo/
accountId: 12345
stages: [Регистрация, Прогрев]
nodes:
  - id: reg-page
    stage: Регистрация
    kind: page
    title: Страница регистрации
    purpose: Собирает заявки на бесплатный вебинар
    source: webinar-demo/landing/
  - id: registrations
    stage: Регистрация
    kind: table
    title: Заявки
    purpose: Хранит заявки с формы
    source: webinar-demo/tables/registrations.table.ts
  - id: warmup
    stage: Прогрев
    kind: series
    title: Прогрев, 1 письмо
    purpose: Подтверждает регистрацию и напоминает об эфире
    source: .mailings/storage/processes/webinar-demo/warmup/
links:
  - from: reg-page
    to: warmup
    when: сразу после регистрации
    signal: event:registration_created
    via: webinar-demo/automations/warmup/
```

## Поля

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `title` | да | Название процесса для человека |
| `knowledge` | да | Раздел процесса в базе знаний |
| `letters` | если есть серии | Папка писем процесса в хранилище |
| `accountId` | если есть автоматизации | Числовой id аккаунта для `routeJson`. Узнать: `chatium exec` → `return ctx.account.id` |
| `stages` | да | Этапы пути клиента по порядку — колонки карты |
| `nodes[]` | да | Узлы: что есть в процессе |
| `links[]` | нет | Стрелки: что за чем происходит |

**Узел:**

| Поле | Что это |
| --- | --- |
| `id` | Уникальный слаг узла латиницей |
| `stage` | Один из `stages` |
| `kind` | Вид кубика: `page`, `table`, `series`, `payment`, `crm`, `external` |
| `title` | Название для человека: «Прогрев, 4 письма», а не `warmup` |
| `purpose` | Зачем узел бизнесу, одной фразой |
| `source` | Путь от корня аккаунта: папка или файл, где это построено |

**Стрелка:**

| Поле | Что это |
| --- | --- |
| `from`, `to` | `id` узлов |
| `when` | Человеческая подпись: «через день в 10:00», «если не оплатил за сутки» |
| `signal` | Что запускает переход: `event:<ключ>` из `specs/events.yaml` |
| `via` | Папка автоматизации, которая реализует стрелку |

## Правила

- Автоматизация — не узел, а стрелка с `via`: для бизнеса это «после
  регистрации → письма».
- Серия писем — один узел; письма раскрываются из папки `source`.
- Таблица — узел вида `table`; на экране она станет счётчиком «Заявки: 124».
- Подписи человеческие, без `delay: 86400` и имён файлов.
- Всё построенное должно попасть в карту. `check` считает провалом:
  - узел, чей `source` не найден, — «не построено»;
  - страницу, автоматизацию или серию в коде, которой нет в карте, —
    «неучтённое». Обнови карту.
