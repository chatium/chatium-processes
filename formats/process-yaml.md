# Карта процесса: `<process>/process.yaml`

Карта — смысл процесса на языке бизнеса плюс технические якоря. По якорям
`check` проверяет, что всё построено, а экран процесса и аналитика считают
людей. Пишет и поддерживает карту агент; статус узла в карту не пишется —
его даёт `check`.

## Пример

Каркас процесса «страница с формой → серия писем». `<…>` — заглушки:
подставь своё. Этапы и узлы у каждого процесса свои.

```yaml
title: <Название процесса для человека>
knowledge: .knowledge-base/processes/<process>/
letters: .mailings/storage/processes/<process>/
accountId: 12345
stages: [Заявка, Касания]
nodes:
  - id: form-page
    stage: Заявка
    kind: page
    title: Страница с формой
    purpose: <Что клиент делает на странице и зачем это бизнесу>
    source: <process>/<page>/
  - id: requests
    stage: Заявка
    kind: table
    title: Заявки
    purpose: Хранит заявки с формы
    source: <process>/tables/<entity>.table.ts
  - id: followup
    stage: Касания
    kind: series
    title: <Название серии, N писем>
    purpose: <Что серия даёт клиенту>
    source: .mailings/storage/processes/<process>/<series>/
links:
  - from: form-page
    to: followup
    when: сразу после заявки
    signal: event:<key>
    via: <process>/automations/<automation>/
```

## Поля

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `title` | да | Название процесса для человека |
| `knowledge` | да | Раздел процесса в базе знаний |
| `letters` | если есть серии | Папка писем процесса в хранилище |
| `accountId` | если есть автоматизации | Числовой id аккаунта для `routeJson`. Узнать: `chatium exec` → `return ctx.account.id` |
| `stages` | да | Этапы пути клиента по порядку — колонки карты |
| `nodes[]` | да | Узлы: что есть в процессе |
| `links[]` | нет | Стрелки: что за чем происходит |

**Узел:**

| Поле | Что это |
| --- | --- |
| `id` | Уникальный слаг узла латиницей |
| `stage` | Один из `stages` |
| `kind` | Вид компонента: `page`, `table`, `series`, `payment`, `crm`, `external`, `agent` |
| `title` | Название для человека: «Напоминания, 3 письма», а не `reminders` |
| `purpose` | Зачем узел бизнесу, одной фразой |
| `source` | Путь от корня аккаунта: папка или файл, где это построено |
| `creativeRef` | Для новой страницы или серии: путь от корня аккаунта к её `creative/<node-id>/spec.yaml`; `creative.mjs` раскрывает его в `build.md` |
| `agentId` | Только для узла с `source: <путь>.agent.json`: необязательный runtime ID агента, если он известен. Не путать с `id` узла |

**Стрелка:**

| Поле | Что это |
| --- | --- |
| `from`, `to` | `id` узлов |
| `when` | Человеческая подпись: «через день в 10:00», «если не оплатил за сутки» |
| `signal` | Что запускает переход: `event:<ключ>` из `specs/events.yaml` |
| `via` | Папка автоматизации, которая реализует стрелку |

## Правила

- Автоматизация — не узел, а стрелка с `via`: для бизнеса это «после
  заявки → письма».
- Серия писем — один узел; письма раскрываются из папки `source`.
- Для агента используй `kind: agent` и `source` его `.agent.json`. Опиши роль и связи по [формату агентов](agents.md). Снимок сохранит путь, а при наличии `agentId` — и runtime ID. Не придумывай ID, если его пока нет.
- Таблица — узел вида `table`; на экране она станет счётчиком «Заявки: 124».
- Подписи человеческие, без `delay: 86400` и имён файлов.
- Всё построенное должно попасть в карту. `check` считает провалом:
  - узел, чей `source` не найден, — «не построено»;
  - страницу, автоматизацию или серию в коде, которой нет в карте, —
    «неучтённое». Обнови карту.

## Нужно от вас

Необязательное `needsInput` — конкретные незакрытые действия владельца.
Записывайте их в карту вместе с PLAN.md, чтобы они появились на экране.

```yaml
needsInput:
  - title: Утвердить темы писем
    nodeId: followup
  - title: Подключить канал Sender
```

`nodeId` необязателен; если задан, это существующий id узла. Уберите пункт
после выполнения. Статусы узлов по-прежнему вычисляет check.
