# Chatium processes skill

Скилл `processes` помогает проектировать, собирать и проверять бизнес-процессы
в Git-аккаунте Chatium. Рабочие инструкции находятся в [SKILL.md](SKILL.md).

Версия установленного скилла — точный коммит исходника и SHA-256 содержимого
установочных файлов. Они записаны в `.agents/skills/processes/INSTALLATION.json`
аккаунта. Для быстрой проверки открой этот файл; для сравнения с опубликованным
`main` из checkout исходника выполни:

```sh
node .github/sync-skill.mjs status '/путь/к/Git-аккаунту'
```

`status` также обнаруживает старые копии без `INSTALLATION.json`: покажет, совпадают
ли их файлы с текущим выпуском, хотя точный старый коммит без метки неизвестен.
Хэш содержимого не меняется от правок служебных `.github/` и этого README.
Поле `version` в `package.json` — метаданные npm, не версия выпуска скилла.

Установка и обновление делаются **по просьбе пользователя**. После проверки
чистого состояния и `git pull --ff-only` в аккаунте выполни из checkout
исходника:

```sh
node .github/sync-skill.mjs install '/путь/к/Git-аккаунту'
```

Команда берёт опубликованный `main`, переносит отслеживаемые Git-файлы **без
`.git`, `.github`, `node_modules`, корневого `README.md` и локальных записей** в
`.agents/skills/processes/` (включая удаления), записывает версию и ставит
зависимости через `npm ci --ignore-scripts`. Затем проверь diff и совместимость,
закоммить и опубликуй аккаунт отдельно. Папка скилла и `INSTALLATION.json`
должны отслеживаться Git аккаунта: обычный `git pull` доставит их в новую среду.
Не обновляй скилл автоматически перед каждой задачей.

В аккаунте также должен быть скилл `chatium-development`. Требования к
окружению и доступу к Chatium описаны в [build/environment.md](build/environment.md).

Штатная команда устанавливает опубликованную версию `main`; для выбранного тега
нужна отдельная ручная установка с такой же меткой версии.
Локальные незакоммиченные правки в этом репозитории не входят в такую версию.
`.github/` содержит CI и журнал разработки; эти файлы не входят в работающий
скилл. Проверяй состав копии перед коммитом аккаунта.

Версия для независимого тестировщика проверяется командами `npm test` и
`npm run check:tester`. Открытые содержательные и живые сценарии перечислены
по ID в `.github/REMEDIATION-REGISTER-2026-10-07.md` и распределены по видам
испытаний в `.github/TESTER-DEFERRALS.json`. Это кандидат для испытаний, а не
подтверждение готовности боевого процесса. Полный выпуск дополнительно требует
`node .github/release-check.mjs` и сквозных прогонов на чистой установке.
