# Компетенции одного специалиста

Один специалист отвечает за цельный результат. `executor.role` определяет
тип поручения, профили — профессиональные компетенции, знания и материалы
задачи — нишу и бизнес. Состав хранится в [catalog.json](catalog.json).
`tasks prepare` добавляет обязательные профили автоматически;
`executor.profiles` только дополняет этот набор.

| Роль | Обязательные профили | Когда применять |
| --- | --- | --- |
| `landing` | marketing, copywriting, design | Страница с предложением и действием |
| `site` | marketing, copywriting, design, product | Структура сайта и путь между страницами |
| `confirmation` | copywriting, design | Подтверждение, только `landingType: thankyou` |
| `email` | marketing, copywriting, communications | Серия сообщений, включая мессенджеры |
| `message` | copywriting, communications | Сложное отдельное служебное сообщение |
| `agent` | product, dialogue, copywriting | Роль и разговоры клиентского ИИ-помощника |
| `consultant` | Указанные в `executor.profiles` | Конкретный вопрос выбранным компетенциям |

Простую техническую страницу или короткое уведомление основной агент может
сделать сам по действующим правилам. Наличие роли не делает её обязательной.
`site` может готовить общее решение одной карточкой; реальные страницы
сохраняют свои задания и проверки. `message` не заменяет `email` у серии.
Для продающего агента добавь `marketing`.

Прежние `marketing` и `copywriter` — совместимые роли с одним соответствующим
профилем; `reviewer` сохраняется. Для новой консультации используй
`consultant`. Заключения комиссии по-прежнему готовятся через `reviews`
и специальные команды ревью; карточка консультанта их не заменяет.

## Комбинирование

```json
{ "kind": "specialist", "role": "landing" }
```

Один специалист получает маркетинг, копирайтинг и дизайн. Даже
`profiles: ["design"]` не уберёт другие обязательные компетенции.

```json
{ "kind": "specialist", "role": "email", "profiles": ["design"] }
```

Автор серии дополнительно прорабатывает арт-направление. Штатная методика
email-вёрстки включена у `email` и без дополнительного профиля.

```json
{ "kind": "specialist", "role": "consultant", "profiles": ["marketing", "product"] }
```

Узкая консультация, например сравнение двух предложений. Назови вопрос,
варианты, основания сомнения и ожидаемое решение. Не запускай консультанта
автоматически к каждой странице. Несколько профилей — один вызов, одно
предложение, одна общая самопроверка.

## Бриф и качество

В `inputs` передай конкретные знания и материалы бизнеса, смежные условия
и нужные референсы. Основной агент обеспечивает достаточность входов;
специалист восстанавливает краткий бриф с источниками. Нишу не надо
кодировать постоянной ролью; бриф не создаёт второй реестр цен и фактов.
Обязательные методики качества входят в prompt; каталоги типов, стилей,
механик и подачи читаются выборочно через `catalog.mjs`.

Критерии карточки отражают реальный результат: выбранная аудитория и причина
выбора, последовательность аргументов, готовые ключевые тексты, подача и
действие. Например: «Читатель понимает, что сделает сам, почему справится
без опыта, когда получит результат и что произойдёт после заявки;
утверждения подтверждены материалами». «Заполнены все секции» недостаточно.
Служебному подтверждению не нужны три концепции и длинная продажа.

Специалист предлагает, основной агент принимает и реализует. Отклонение
существенного предложения зафиксируй с причиной в предложении или приёмке
карточки. При переносе в `spec.yaml` сохраняй аргументацию, точные тексты и
конкретные визуальные решения, проверяй согласованность целого.

## Передача и проверка

`tasks start` фиксирует состав компетенций и хеши инструкций в попытке.
`tasks prepare` создаёт `prompt.md` с полным текстом общей инструкции, роли,
выбранных профилей и обязательных методик. Передай **весь этот текст** в
стартовое поручение одного субагента, не только путь или пересказ.
В `packet.json` находятся бизнес-материалы и манифест версий. После запуска
выполни `tasks bind`. Не меняй пакет после подготовки.

Ответ JSON из prompt содержит `contractDigest`, краткий `brief`, цельный
`proposal` и по одному `profileApplications` на профиль (`id`, `decision`,
точная `proposalQuote`). Основной агент сохраняет предложение в ожидаемый
файл и передаёт исходный JSON через `responseRef` при `record`.
Скрипт проверяет версию, полноту профилей и цитаты в ответе и сохранённом
предложении. Одна общая цитата для всех компетенций не принимается.
Краткое подтверждение сохраняется в карточке: уборка временного пакета
после приёмки не уничтожает сведения о применённых профилях.

Эти проверки выявляют пропуск и рассинхронизацию, но не доказывают авторство,
осмысленное чтение или экспертное качество. Основной агент проверяет
предложение через `inspection`. Независимое творческое ревью spec и результата
оценивает позиционирование, тексты и согласованность одним заключением.
Отдельное ревью на каждый профиль не требуется. Замечания версии исправляй
одним пакетом, соблюдая общий бюджет повторов комиссии.

Изменение выбранного профиля, роли или обязательной методики меняет отпечаток
задачи; неиспользованные профили его не меняют. После обновления скилла
прочитай `tasks status`, возобнови затронутые задачи через `reopen` и `start`.
Старые роли и предложения сохраняются. Новый ответ нужен попыткам,
начатым с контрактом компетенций; исторические ответы не переписывай.
