# Компонент: CRM

**Для бизнеса.** Клиенты и контакты, заказы с составом и историей оплаты,
компании-плательщики, сегменты и работа сотрудников с этими данными.

## Сначала выбери владельца данных

Заказ или продажа — сделка CRM (`createDeal` из `@crm/sdk`), а не собственная
таблица `orders` с суммой, оплатой и статусами. CRM хранит номера, позиции,
контакты, историю, этапы и оплату; процесс не создаёт их параллельную копию.
Используй готовую карточку CRM вместо собственного экрана менеджера заказов.

Собственные таблицы нужны предметной области: бронь места, посещение,
доступ к курсу, заявка с особыми полями. Свяжи такую запись со сделкой через
`subject: { heapType, id }`; при необходимости сохрани `dealId` как ссылку.
Бронь и заказ имеют разные состояния: не переноси расчёт оплаты в бронь.
Если предметных данных нет, отдельная таблица для создания заказа не нужна.
Обычное обращение без покупки может оставаться заявкой с задачей сотруднику;
создавать сделку ради каждой формы не требуется.

## Создание и чтение заказа

```ts
import { createDeal, getDeal, ContactType } from '@crm/sdk'

const view = await createDeal(ctx, {
  idempotencyKey: `enrollment:${submission.id}`,
  title: 'Участие в занятии',
  contacts: [{ type: ContactType.Email, value: submission.email }],
  customer: { displayName: submission.name },
  sourceSystem: 'class-booking',
  currency: 'RUB',
  items: [{ name: 'Занятие', quantity: 1, price: serverPrice }],
  subject: { heapType: enrollment.heapType, id: enrollment.id },
  returnUrl: '/class-booking/result',
  paymentCallback: dealPaymentChanged,
})
const dealId = view.deal.id
const paymentUrl = `/app/crm/pay?deal=${encodeURIComponent(dealId)}`
```

Здесь `submission`, цена, предмет и callback — данные и обработчик процесса,
не готовые глобальные переменные. Ключ повтора относится к одному обращению;
email не является ключом заказа. Повтор `createDeal` возвращает исходную сделку
и не перезаписывает правки сотрудника. Следующая покупка получает другой ключ.
Сумму, состав, предмет, callback и адрес возврата определяет сервер.

`DealView` содержит `deal`, `contacts`, `customers`, `customerResolution`,
а также позиции и компанию. ID — `view.deal.id`, не `view.id`.
Сделка связана с контактами, поля `deal.customerId` нет. Передавай только
контакты этого обращения через `contacts`/`contactIds`, не все контакты
найденного клиента. `customerResolution: ambiguous` означает несколько
клиентов; нельзя выбирать первого или раскрывать их данные друг другу.
Нормализацию и поиск личности выполняет CRM.

`getDeal(ctx, { id })` читает актуальную сделку. `findDeals` возвращает
`{ deals, total, offset, limit }` (до 100 за запрос), `countDeals` — число.
Используй фильтры по источнику/предмету, контакту, статусу и периоду;
не загружай весь аккаунт для выбора заказов одного процесса.
Наличие ID не доказывает право пользователя читать или изменять заказ.

## Возможности вместо собственной реализации

| Задача | Штатный механизм |
| --- | --- |
| Состав, количество, скидка, НДС, сумма | `createDeal({ items, currency })`, `setDealItems`; итог считает CRM |
| Изменение условий, ответственного и этапа | `updateDeal`; существующие воронки и этапы CRM |
| Контакты и предмет | `linkDealContacts`, `unlinkDealContacts`, `setDealSubject` |
| Оплата, остаток, платёжная страница, регулярное списание | [Оплата заказа](payment.md) |
| Компания-плательщик и её сотрудники | `createCompany`, `getCompany`, `findCompanies`, `updateCompany`, `linkCompanyMembers`; `companyId` сделки |
| Сегменты клиентов | Коллекции CRM: `createCollection`, `addCollectionCustomers`, методы чтения состава |
| Связи с предметными записями | `linkRecords`/`record`, `findCustomerLinkedRecords`; штатные расширения карточек CRM |
| Исторические заказы | `importDeal` с `externalSystem` + `externalId`; импорт не пишет обычные события новой сделки |
| Убрать заказ из работы | `archiveDeal` / `restoreDeal`; не удаление таблицы или истории оплаты |

Номер выдаёт CRM. `amount` без значения — неизвестная цена, `amount: 0` —
бесплатный заказ. Непустые `items` включают расчёт суммы по позициям;
не переписывай `amount` собственным итогом. Статусы работы `open/won/lost/archived`
независимы от `paymentStatus`: `won` не доказывает оплату.
Перед добавлением недостающего метода проверь установленные typings:
наличие административного HTTP API не означает наличие такого же SDK-метода.
Настройки платёжных страниц и воронок выбирай в штатном интерфейсе CRM;
не импортируй приватные таблицы плагина для их изменения.

## События и сообщения

CRM сама публикует `event://crm/deal/created`, `stage-changed`, `won`, `lost`,
`archived`, `restored`, `payment-changed`, `paid`, `contact-linked`, `contact-unlinked`.
Используй эти URL в `eventUrls`, не создавай второе событие того же факта.
В карте можно указать полный URL в `signal`; местные события сохраняют
`event:<ключ>`. Платформенный URL не регистрируется повторно в `events.yaml`.

В автоматизации доступны `event.dealId` и поля из фактического
`getAccountEvents`/`payloadMapping`; прочитай заказ через `getDeal` и проверь
его принадлежность процессу по серверному `sourceSystem`, предмету и принятому
контракту. События CRM общие для аккаунта: нельзя реагировать на все оплаты
чужих процессов. Контакты события — контакты сделки; у `contact-*` это только
изменённые контакты. Данные события могут устареть к моменту выполнения.

CRM уже отправляет системные уведомления Store сотрудникам согласно их
настройкам и ответственному. Не дублируй их автоматически. Письма клиенту,
выдачу результата и остановку серии проектирует процесс через свои действия.
Самостоятельные факты процесса, например выдачу доступа, записывай через
`captureCustomerEvent` с `contacts`; CRM формирует `customer_contacts` сама.
Правила контактов и метрики — [events-yaml.md](../formats/events-yaml.md).

## Работа сотрудников

Задачи сотрудников принадлежат плагину `tasks`, не таблице заказов CRM
и не карточкам разработки `<process>/tasks/W*.json`. Если нужен звонок,
разбор заявки, срок и ответственный, проверь установку `tasks` и его `@tasks/sdk`.
`createTask` принимает ключ повтора, заголовок, контакты, предмет, сроки
и воронку; точные поля читай в установленных типах. CRM предоставляет
`findTaskSubjectOptions`, `previewTaskTargets`, `snapshotTaskTargets`,
`readTaskTargetPage`, `resolveTaskTarget` для выбора связанных записей и
аудиторий. Задача сотруднику не заменяет обещанное сообщение клиенту.

## Проверка

Проверь повтор создания, разные покупки одного клиента, контакты нескольких
клиентов, доступ к чужому заказу и связь с предметом. Сохраняй изменения
менеджера при повторе формы. Для оплаты используй [сценарии Pay + CRM](payment-testing.md).
Для передачи клиента в мессенджер —
[sender-linking.md](../../chatium-development/sender-linking.md).
