# Методология

Сначала прочитай [интервью](interview.md) и [критерии готовности](readiness.md).
После первичных вводных сам найди публичные сведения именно об этом бизнесе
и сверь все находки с владельцем по [правилам поиска](interview.md#самостоятельный-поиск-о-бизнесе).
Собирай знания в форме, соответствующей бизнесу: темы можно объединять
в одной статье или разделять. Названия тем и рубрики справок не становятся
обязательными названиями файлов или заголовками статьи. Выбирай композицию
по содержанию и читателю, включая короткий текст без разделов.
Число файлов, страниц, писем и возражений
само по себе ничего не говорит о качестве.

| Тема | Когда читать |
| --- | --- |
| [Суть](topics/essence.md) | Цель, результат, механизм и границы процесса |
| [Аудитория](topics/audience.md) | Сегменты, вход, контекст решения, препятствия |
| [Предложение](topics/offer.md) | Ценность, состав, цена/обмен, условия и ограничения |
| [Путь клиента](topics/journey.md) | Этапы, переходы, альтернативы, повторы и завершение |
| [Страницы и формы](topics/pages.md) | Если путь включает страницы или сбор данных |
| [Коммуникации](topics/communications.md) | Сообщения, серии, звонки и прекращение контактов |
| [Исполнение](topics/operations.md) | Доставка результата, ответственные, зависимости и измерение |
| [Помощники](topics/ai-agents.md) | Где ИИ полезен на пути клиента, что согласовано и где нужен человек |
| [Особенности бизнеса](topics/business-specific.md) | Материалы и правила, которые не укладываются в общие темы |

В каждой теме есть вопросы, признаки достаточности, ошибки и пример.
Вопросы используй для собственного поиска пробелов, а не как анкету
пользователю. Веди интервью по одному следующему решению: прочитай имеющееся,
спроси недостающее, сохрани ответ, помоги его осмыслить и выбери следующий шаг.
Полнота тем проверяется перед сдачей этапа, а не требуется для начала разговора.
Факты, гипотезы, согласованные решения и зависимости различаются
по [readiness.md](readiness.md).

После наполнения обязательны две проверки по [review.md](review.md):
`kb-check` проверяет структуру; отдельный субагент — содержание по
[рубрике вопросов](review-questions.json). Выбирай готовность к проектированию,
сборке или запуску. Доказательство — актуальный отчёт с источниками,
а не субъективное «кажется, материала достаточно».

Формат статей и выбор шаблонов — [knowledge-base.md](../formats/knowledge-base.md).
